# 第6次 番組発見・公開運用

## 段階と実行環境
発見（AI Web検索）→検証（個別放送日時・内容・取得利用の根拠）→公開（既存Actions/Pages）の3段階。
config/discovery.jsonは全20ジャンルの代表番組・ジャンル語・公式ドメイン・番組表入口を管理する。
python scripts/discovery.py --plan は各ジャンルの番組名検索、ジャンル検索、公式番組表確認の60項目を生成する。これは検索実行ではない。
AIタスクは利用可能なWeb検索ツールで計画を実行し、実際に使ったquery/tool/checkedAt/route/statusをdata/ai-candidates.jsonのresearchへ記録する。検索できない環境では実行したと装わず不足として記録する。
GitHub ActionsはWeb検索AIを内蔵しない。既存ChatGPTタスクが候補JSONをGitHub連携で書き込んだpushが接続点である。有料AI検索APIは追加しない。

## ほん怖の原因と限定修正
発見済み、候補JSONあり、公式発表・公式番組ページで2026-10-31 21:00〜23:10 JST、フジテレビ、心霊・怪談を確認済みだった。
第5次のofficial_unreviewed一律判定で保留となり、公開JSONに存在しなかった。Android絞り込みに到達する前の問題。
10/26の「今日」には日付上も出ない。「1週間」で10/31が対象となる。心霊・怪談ON、お気に入り限定OFF（または保存済み）が表示条件となる。

文化庁の説明は、単なる事実・データなど著作物でないものは許諾なく利用できるとしている。
https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/chosakukensha_fumei/
一方、フジテレビは本文・画像等の権利と利用条件を掲示している。
https://www.fujitv.co.jp/safe/userguide/iprights.html

今回の運用判断は、本文や写真、ロゴ、出演者、番組表の選択配列を転載せず、当該公式発表から放送の最小事実だけを独自に整理する範囲に限定するもの。フジテレビが自動取得・転載を許可した、又はライセンスを付与したとは主張しない。単なる事実の利用と著作物の転載を一律に同じ扱いにしていた判定を改めた。
source-policy.jsonのfuji_honkowa_minimal_factは出典URL・番組名・局・開始終了日時・ジャンルを固定し、ai_web_referenceによる個別確認だけを受け付ける。次回の別日付、他番組、別URL、本文付き候補、バルクスクレーパーはこの規則で通さない。サイト全体の自動利用許可へ拡張していない。他の14候補等の未確認条件を自動的に解除しない。
公開情報の最小事実を独自に整理する方法は、包括的な番組表ライセンス以外の選択肢になる。ただし、別サイトの契約・アクセス条件やデータベースの複製範囲は個別に評価する。

## 品質確認
python scripts/discovery.py --quality がdata/collection-quality.jsonを生成する。
候補数、新規・更新、候補内重複、公開済み件数、保留数、理由別件数、将来の未公開枠、未公開の注目番組、20ジャンル別検索実績と公開件数を記録する。
理由は日時不足、局不足、分類不足、利用条件未確認、重複、期間外、その他を区別する。複数理由の件数は候補数と合計一致するとは限らない。
「検索したが確認候補なし」は「番組が存在しない」とは違う。検索記録がない0件ジャンルは調査不足と明示する。実行されていない計画を検索実績に数えない。
公開前はvalidated_candidate_not_yet_deployed、Pagesの全JSON照合が通った後はcurrent_public_jsonとなる。候補が保留でも以前から同じ内容が公開中の場合は、保留状態と公開状態を別々に記録する。

## 保留再評価
data/phase6-reevaluation.jsonに元の16候補を個別記録した。13:40のロビン・フッドは開始済み。ほん怖は限定した事実利用の検証対象。健康カプセルの個別ページはツールで取得失敗し最新の再確認完了としない。その他は公式日時と分類を再確認したが、情報源ごとの自動利用条件は引き続き未確認。

## 継続運用と制約
既存の月曜・木曜09:00 JSTを維持し、日曜通知に触れない。通常成功は件数ログのみ。取得・公開失敗、矛盾、未公開の注目番組、検索機能不足は具体的に報告する。
既存ChatGPTの利用枠・権限・実行環境に依存する。無人定期実行の検索・GitHub書込みが観測できるまでは、対話中の成功と区別する。
GitHub Pages、既存v0.2.0とキャッシュ保持を継続。追加契約、有料API、Cloudflare、不要なAPK再ビルドを行わない。
