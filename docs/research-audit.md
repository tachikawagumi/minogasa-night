# 調査証跡・完了判定（試験導入）

目的：ChatGPTの「調査した」という自己申告だけで完了にしない。既存の番組収集・公開処理は変更しない。

## 記録単位
1回の調査（JSTの開始日から7日間）につき `data/research-audits/YYYY-MM-DD.json` を作る。20ジャンルそれぞれに、実際に確認した検索語・対象日・検索元URL・確認した日時・確認件数・登録件数・打切り理由を残す。

## 判定
- **未着手**：検索証跡がない
- **途中**：7日分または予定検索語に未確認がある／途中打切りがある
- **完了（記録上）**：20ジャンルの予定検索語・7日分が全て確認済み、途中打切りなし、検索元URLと確認日時あり
- **公開済み**：上記とは別にGitHub Actionsと公開JSONを照合して判断する

「完了（記録上）」は検索先の全番組を網羅した保証ではない。検索結果が多く確認しきれなければ必ず「途中」。証跡は実際の検索後にだけ記入し、未実施を完了にしてはならない。

## 運用
- Gガイド・J:COMの既存ジャンル別キーワード検索と重点番組の個別確認を維持する。ジャンル別の無差別大量収集はしない。
- 調査結果0件でも、検索証跡があれば完了可能。
- アニメAPI取得は検索の代わりにAPI実行結果・取得件数・日時を記録。
- 検索できなかった日や語は空欄ではなく未確認として残す。
- 既存の `data/collection-quality.json` は候補品質管理、こちらは**実作業の証跡**であり別物。
- 次の段階で、証跡の自動検証スクリプトと未完了一覧を作る。検証導入前は自己申告の完了表示をしない。

## 番組発見の基本方針（2026-11-09確定）
**Gガイドの詳細ジャンル一覧は入口であり、網羅の保証ではない。** 番組表のジャンル分類から漏れた番組も独自に発見する。『Dの旋律』がダンス一覧に見当たらなかったという指摘は、一覧だけに依存しない理由の例（該当週の掲載漏れを検証済みという意味ではない）。

調査は次の3系統を**併用**し、どれか一つで済ませない。
1. **詳細ジャンル週間一覧**：対象ジャンルに対応するGガイドの詳細分類を7日分、ページ送りを含めて確認。映画＝今週の映画、野球・ゴルフ・サッカー＝スポーツの各競技、車＝車・バイク、旅＝旅・釣り・アウトドア＋バラエティ／旅バラエティ、釣り＝旅・釣り・アウトドア。その他は該当分類が有用な場合のみ利用。無関係な全ジャンルの一括巡回はしない。
2. **独自キーワード・当該回内容検索**：番組名だけでなく番組説明やコーナーを調べ、ジャンル一覧に出ない番組を補完。Gガイド・J:COMの対象ソースを基本とする。
3. **重点番組の個別確認**：『Dの旋律』（ダンス）、『新しいカギ』（学校かくれんぼ等）、『午後のロードショー』『金曜ロードショー』等、ジャンル一覧に出なくても番組ごとに放送予定と当該回内容を確認する。重点番組は既存のconfig/discovery.jsonを参照・更新する。

### 判定・登録
- 対象は東京・千葉の地上波と無料BS、調査時点から7日先（JST）。有料CS・配信のみは除外。
- 番組名・局・放送日・開始時刻をGガイドまたはJ:COMの一方で確認できれば登録候補にできる。公式サイト再確認や二重ソース確認は必須ではない。ジャンル適合は番組内容で判断する。
- 同一番組が一覧・キーワード・重点番組検索の複数経路に出ても、放送局と開始日時を照合して重複登録しない。
- **調査完了**は3系統の予定作業について実施証跡が揃い、7日分・必要なページ・重点番組の未確認がなく、途中打切りがない場合のみ。詳細ジャンル一覧だけの確認で完了にしない。
- 証跡には系統別に調査URL・検索語／分類・対象日・確認日時・確認件数・未確認範囲を記録する。実施していない作業の証跡を作らない。
- **公開完了**は別判定。GitHub Actionsと公開JSONの反映を確認するまで公開済みとは言わない。

この文書は**運用指示**であり、自動実行・自動証跡・自動完了判定の実装済みを意味しない。既存の調査自動化がこの3系統を実行したかは、実際のログで検証する。
