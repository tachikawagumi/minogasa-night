# 第13次：発見品質と定番番組追跡
docs/phase12/OPERATIONS.md の起動記録・既存データ保護・書込/公開検証を継承する。回数を完了条件にする規則は、本書の探索方式に置き換える。

## 探索の順序
1. config/regular-programs.json と公開JSONを読む。全20ジャンルで広域検索し、特番・大会・単発回も探す。
2. 定番リストの各項目を個別追跡する。過去/終了/未確認と現行を分け、今回の局・日付・内容を確認する。曜日から枠を生成しない。
3. 放送局別の週間表・日付付き個別ページを確認する。汎用ホームの古い次回表示だけで打ち切らず、検索語とページの種類を変える。
4. 0件、極端に少ない、末尾2日に予定がないジャンルを再検索する。ディズニー/USJは情報番組内特集も、ゴルフは女子/男子/海外無料/レッスンも調査する。
5. 既存の条件付き公開処理へ渡し、新IDのPages取得を確認する。

## 終了判断
検索回数を成果にしない。新しい定番・大会・放送局の探索で候補が増える間は追跡する。候補が重複し、出典の確認範囲が充足し、追加発見が減った時点で終了理由を記録する。0件は不存在の証明ではない。不明な局・日時・回の内容は保留する。
regular-programs.jsonは検索補助資料であり、公開処理は読み込まない。定番に載っただけで公開しない。

## 記録と定期タスク
既存run記録へ regularTracking:[{id,result}] と20ジャンル別の新規/重複/保留/不足点を記録する。定番リスト自身のlastCheckedAt/lastResult/lifecycleの更新は、同じ参照IDの確認結果のみ変更可能。参照先の追加・現行と過去の判定は実際の確認に基づく。
既存有効個別ポリシーの既存ホスト内で対象URL/個別審査を追加する制約は維持する。未知のホストの許諾をタスクが勝手に広げない。
Gガイドは今回、情報再提供・類似サービス構築・継続自動取得の制約を確認したため、同サイトのみを根拠とする公開をしない。週間規則や他年の告知で代用しない。
アニメAPI重複照会、公開JSON直接編集、APK変更、正常データ保護の弱体化をしない。開始記録→実検索→GitHub書込→Actions→Pagesの各証跡を残す。
月曜・木曜09:00 JST、次回2026/11/2。定刻の完全無人成功は実際の起動・検索・書込・公開が揃うまで未検証。通常成功はログのみ、失敗・必要操作のみ通知。
